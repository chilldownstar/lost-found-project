# 🔍 نظام المفقودات والموجودات - جامعة تبوك

نظام ويب بسيط بلغة PHP وقاعدة بيانات MySQL لإدارة العناصر المفقودة والموجودة داخل الجامعة، مع لوحة تحكم للمسؤول.

**تطوير:** الطالب علي محمد — قسم تقنية المعلومات، كلية الحاسبات وتقنية المعلومات، جامعة تبوك.

## ✨ المميزات

- عرض العناصر المفقودة/الموجودة للزوار في الصفحة الرئيسية
- لوحة تحكم للمسؤول (Admin) محمية بتسجيل دخول
- إضافة، تعديل، حذف العناصر مع رفع صورة لكل عنصر
- تغيير حالة العنصر (قيد المراجعة / مقبول / تم الاستلام)
- إحصائيات سريعة في لوحة التحكم

## 🏗️ هيكل المشروع

```
├── index.php              # الصفحة الرئيسية (عرض عام)
├── config.example.php     # قالب إعدادات الاتصال بقاعدة البيانات
├── includes/
│   ├── header.php
│   └── footer.php
├── admin/
│   ├── login.php
│   ├── logout.php
│   ├── dashboard.php

│   ├── edit_item.php
│   └── manage_items.php
├── uploads/                # صور العناصر المرفوعة (فارغ في الريبو)
└── database/
    └── lost_found_project.sql
```

## 🚀 التشغيل محلياً

1. ثبّت XAMPP أو أي بيئة PHP + MySQL محلية.
2. استورد قاعدة البيانات من `database/lost_found_project.sql` (أنشئ قاعدة بيانات باسم `lost_found_project` أولاً).
3. انسخ `config.example.php` إلى `config.php` وعدّل بيانات الاتصال حسب بيئتك.
4. ارفع مجلد المشروع داخل `htdocs` (أو المسار المكافئ) وشغّله عبر المتصفح.

### ⚠️ مهم: تفعيل حساب الأدمن الافتراضي

كلمة المرور المخزّنة افتراضياً في ملف SQL هي نص عادي (`admin`) غير مشفّرة، بينما صفحة تسجيل الدخول تستخدم `password_verify()` الذي يتطلب كلمة مرور مشفّرة (hash). **تسجيل الدخول لن يعمل** إلا إذا شغّلت أولاً سكربت `change_pass.php` مرة واحدة بعد الاستيراد لتوليد كلمة مرور مشفّرة صحيحة لحساب `admin`.

## 🔒 ملاحظات أمنية قبل الرفع أو النشر العام

- **`change_pass.php`**: هذا سكربت بدون أي حماية يقوم بإعادة تعيين كلمة مرور الأدمن إلى `admin` لأي شخص يفتح الرابط مباشرة. هو مفيد للإعداد الأولي فقط — تم استثناؤه في `.gitignore`، ويُفضّل حذفه تماماً من الخادم بعد أول استخدام أو حمايته بشرط إضافي.
- **`config.php`**: يحتوي على بيانات الاتصال بقاعدة البيانات، لذلك تم استثناؤه من الرفع؛ استخدم `config.example.php` كقالب بدلاً منه.
- لا يوجد حماية CSRF على النماذج (add/edit/delete) — مقبول لمشروع دراسي، لكن يستحق الذكر إذا نُشر فعلياً.
- الاستعلامات تستخدم `real_escape_string` و `intval` بشكل جيد لمنع SQL Injection في أغلب الأماكن.
